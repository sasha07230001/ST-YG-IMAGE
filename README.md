# YG · 插图师

> 让 AI 的每一段剧情都有画面。YG 会一边陪你聊,一边判断「这一幕值不值得画」,自动写好生图提示词,
> 再交给出图渠道生成图片,直接嵌进楼层里。全程自动,也可随时手动接管。
>
> **0.7 起,整条提示词链合并成一次 AI 调用**:选画面、写 tag、维护角色档案、记录这一刻的穿戴、
> 编译成一串英文提示词,全在一次请求里返回(一份 `images / changes / transient` 的 JSON)。
> 「内置 LLM」与「中转站模型」不再是两条链,只决定**这次请求发给哪台模型**,协议、验收、写回、出图逐字相同。
> 最后,AI 编译出的画面词 + 固定正面 + 角色提示词三层合成一串,写进 ComfyUI 工作流的 `%prompt%`。

---

## 它能做什么

### 🖼️ 自动配图,精彩瞬间不错过
- **自动分析剧情**:每次 AI 回复后通读这一段,判断有没有值得画的瞬间——有就画,没有就安静跳过。
- **自动编写提示词**:正向 tag、自然语言、画幅方向、负面词全都自动写好。
- **一次多张**:单楼可出多张图,按剧情节奏依次生成,并发数可调。
- **手动接管**:点楼层上的「生成 tag」按钮即可;写好的 tag 也直接显示在图片卡片上,随时能看能改。

### 🎭 角色外貌永不漂移
- **首次出场自动建档**:正式角色第一次出场就记下发色、瞳色、体型等固定外貌,之后每张图都长一个样。
- **永久变化按剧情位置生效**:染发、剪发、留疤之前的图用旧档案,之后用新档案。
- **临时状态不污染档案**:假发、湿身、包扎这类状态只写进「这一刻的穿戴」,不写进固定外貌(见下面的「角色档案」一节)。
- **档案库跨聊天**:玩家角色等「哪个聊天都同一张脸」的角色,写进档案库即可,每本书各自播种、互不干扰。

### ✍️ 手动提示词生图

楼层「⋯」展开后,调色板旁边多了一枚**钢笔**按钮:自己敲提示词,直接出图。

- 敲的 tag / 负面 / 自然语言会作为**新的一张图**追加到该楼末尾,然后立刻出图;
- **不经过任何模型**,也不改动正文里已有的 tag —— 想改某张图自己的提示词,用那张图的铅笔;
- 画幅可选(渠道锁定了方向时按锁走,这里显示锁定值);
- 「只写提示词」可以不立刻出图,之后在卡片上点「生成图片」;
- 出来的图带一枚「手动提示词」角标,和模型生成的图分得清。

三个入口的分工:

| 入口 | 提示词从哪来 | 结果 |
|---|---|---|
| 楼层「生成 tag」(调色板) | 模型读正文写 | 写新 tag / 覆盖旧 tag |
| 卡片铅笔里的「AI 重写提示词」 | 模型重写那一条 | 原位替换 |
| **楼层钢笔(手动提示词生图)** | **你当场敲** | **追加一条新 tag 并出图** |
### 🗂️ 角色档案:档案库(你手写)+ 本聊天档案(AI 读剧情更新)(0.7 重做)

角色信息分两层,职责完全分开:

| 层 | 存在哪 | 谁能改 | 干什么 |
|---|---|---|---|
| **档案库** | `extension_settings`(跨聊天) | **只有你**。AI 只读,永不改写 | 角色的初始人设 + **触发关键词**(昵称/称号/职业都行) |
| **本聊天角色档案** | `chatMetadata`(只属于这个聊天) | AI 读正文持续更新,你也能手改/回滚 | 这一刻这个角色长什么样、穿着什么 |

工作方式:

- **关键词触发播种**:本聊天正文里提到档案库里某个角色的任一关键词,就把他从档案库复制一份到**本聊天角色档案**;之后这个角色在这一本里独立演化,换本书互不影响。
- **档案库永不被 AI 改动**:AI 写回的只有本聊天档案(`field:"new"` 建档、永久变化、`transient` 这一刻的穿戴),档案库那份是你手写的底稿。
- **每张图实时取词**:出图时角色层不是「上次算好的缓存」,而是当场从本聊天角色档案里取——AI 刚写进去的穿戴,下一张图立刻生效。
- **AI 自己判断该调用谁**:在场判定顺序是「模型在 tag/nl 里点名 → 本楼正文命中关键词 → 上一楼在场者」;一个都没认出就只发通用常驻词,宁可少带人,不把别人的衣服穿错。
- **档案库兜底**:本聊天档案还没播种(或那条档案没词)时,直接用档案库里那份,不会出现「档案页写着 1 条、出图却是 0 个角色」。

两层都写进正向提示词的**角色层**(层序:固定正面 → 角色 → 剧情):

```
最终正向 = 固定正面(质量词/画风), 角色层(档案固定外貌 + 你的追加词 + 此刻穿戴), 剧情层(AI 编译的画面)
```

页面在「角色档案」:上半是档案库(手写、带关键词),下半是本聊天角色档案(带「在场」标记、每条变更的历史与回滚、
「重新播种」);顶部那栏实时显示「此刻角色层会发出的词」——看到什么就是下一张图会发出去的。

> 渠道页的「提示词」区里还有一份**可见列表**:本聊天角色档案里每个角色一行,左边是档案给的固定外貌(AI 维护,只读),
> 右边是你可以随时补的追加词。分层拼接的角色层**直接调用这份列表**,不再另算一遍。

### 🔀 提示词方式:只决定「这次请求发给哪台模型」(0.7 起)

两条口径合并之后,这一项退化成**模型选择**,不再有两套协议:

| | 内置 LLM | 中转站模型 |
|---|---|---|
| 走哪条通道 | 设置页「生成 tag 使用」那个渠道(主 API / 副 API) | 一个 OpenAI 兼容端点(SillyTavern 服务端转发) |
| 干什么 | 选画面 + 写 tag + 维护角色档案 + 记录穿戴 + 编译英文提示词,**一次调用全部完成** | **完全相同** |
| 返回什么 | `{"images":[...],"changes":[...],"transient":{...}}` | **完全相同** |
| 角色档案 / 建档规则 | ✅ | ✅(旧版这条链不做建档,0.7 取消了这个分叉) |
| 上下文装配 / 验收 / 写回 / 出图 | 同一份实现 | 同一份实现 |

> 想用便宜模型或自己的中转站,把这一项切过去即可,画面口径不会变;
> 「开场身份」与「书写规范」两份文案仍然可改,它们是**叠加**在内置契约之上的一段开场,留空就与内置口径一字不差。

### 🚏 中转站:正文 → CLIP 提示词
```
楼层正文 ──清洗──► 分段 ──► 中转站模型 ──英文 tag──► 反净化 ──► 合并恒定词 ──► CLIPTextEncode ──► ComfyUI ──► 楼层卡片
                        │                    ▲            ▲                                        │
                        │                    │            └─ 被降级的词补回来(purge 层)          └─ 排队/进度/取消
                        └─ 有 [[图]] 标记按标记切,否则按张数均分
```
- **渠道**:地址(纯域名自动补 `/v1`)、Key、模型(可一键拉列表)、温度、最大 token、超时;
  点「测试中转站」验证三者都对。
- **请求经 SillyTavern 服务端转发**:没有 CORS 问题,Key 不直连浏览器,也不会出现在公开接口里。
- **验收**:与内置链同一份契约 —— 空回复、JSON 解析不过、图片数不够、建档缺 `hair`/`eyes`、NAI 建档缺 `nl` 都判失败并按设置重试。
- **最大 token 别调小**:一次调用要吐出多张图 + 建档 + 穿戴,默认 4000;设成几百会在右括号前被截断,解析必然失败。
- **自检**:「用当前楼梯自检」走的是**与出图完全相同**的那条路(同一份 messages、同一个协议解析),
  把原文与解析结果一起显示:「解析通过:N 张(P1 portrait / P2 landscape),建档 N 条,穿戴 N 条」。
- **编译提示词可改**:system 提示词(占位符 `{{story}}` `{{note}}` `{{index}}` `{{count}}` `{{orientation}}`)
  与编译规范各一份,留空回落内置默认。
- **分段**:正文里写 `[[图]]` 就在那里切一张,张数以标记数量为准;没标记按张数均分(空行 → 句末标点 → 字符)。
- **恒定词前置**:`画风词, 模型编译的画面, 角色外貌` —— CLIP 对越靠前的 token 越敏感,
  不少工作流只吃前 75 个 token,画风基线丢在末尾等于没写。

### 🧪 purge 层(指令权威 / 反净化)
中转站多半是没打过补丁的官网端点:同样的正文,在别处能照画,到这里常被"润色"成
「两个角色紧张对峙」。这一层补上那段差距,三道闸各自独立可关:
1. **system 前压权威声明**(主路径);
2. **assistant prefill** 用 `POSITIVE:` 起头,让模型续写而不是重新起意
   (端点 400 拒掉时自动去掉 prefill 重发一次);
3. **反净化重写**(兜底):正文有血腥/成人词、输出里没有对应 tag 时按词表补回**正面**,
   绝不补进负面把图洗白。

### 🎨 出图渠道:ComfyUI 与 NovelAI
- **ComfyUI 简易参数**:选模型/LoRA、填步数即可出图(内置 Checkpoint 系/Flux/Anima 模板)。
- **ComfyUI 自定义工作流**:加载你自己的 API 工作流。**没有 `%prompt%` 也能用**——
  客户端会自动找到 `CLIPTextEncode` 节点写入(正向写第一个,负面写带负面词的那个);
  写了 `%prompt% / %negative_prompt% / %seed% / %nl% / %width% / %height%` 则逐字替换,
  其它 `%xxx%` 一律原样保留(不会被当成「不支持的占位符」拒收)。
- **自定义模式也走三层合成**(0.7 起):固定正面 + 角色层 + 剧情层先合成一串,再整体写进 `%prompt%`;
  负面同理走 `%negative_prompt%`(固定负面 + 本图排除)。固定正面/负面就在渠道页「提示词」区那两格里填,两种模式同一份。
- **裸 null 自动补齐**:"Save (API Format)" 导出时未连线的 widget 会写成 `null`(典型是 `EmptyLatentImage.width/height` 与 `KSampler.seed`),
  服务端把它当"显式给了空"直接 400(`int() argument must be ... not NoneType`)。本插件发送前会按当前画幅/种子补上这些 null,
  不会去动你自己给了值的字段。
- **多套工作流随时切换**;横竖尺寸与画幅锁跟着工作流走。
- **NovelAI**:4.5 / V5,支持 vibe 参考图、画师串库、多接入点切换、`.naiv4vibe` 互通。

### 📁 图片管理
- 内嵌楼层卡片、点击放大、长按保存、显示大小四档(小/中/大/铺满)。
- 每张图随图记录完整提示词、画师串、vibe、模型与采样参数;灯箱与图库里点开就能看到当时怎么画的。
- 重绘、取消、**AI 重写提示词**、编辑提示词;智能队列;可选 JPG 转存。

### 🤝 与柏宝书协作
读取柏宝书的角色状态与剧情记忆;排除名单与柏宝书共享(按角色、按世界书整本或按条目名)。

## 安装

在 SillyTavern 的「扩展 → 安装扩展」里填入本仓库地址,或直接把整个目录放进
`SillyTavern/public/scripts/extensions/third-party/`。

安装后:
1. 进「渠道」页配好出图后端(本地 ComfyUI 或 NovelAI);
2. 想用中转站的话,进「提示词」页把提示词方式切成「中转站模型」,填地址/Key/模型,点「测试中转站」;
3. 打开「自动生成 tag」开关,开始自动配图。

设置随 SillyTavern 保存在服务器,跨设备自动同步。

## 构建

```bash
npm install
npm run build     # 产物 dist/index.js + dist/index.css,build 前自动同步 manifest 版本号
npm run typecheck # vue-tsc
```

> `dist/` 是构建产物。改完源码**必须重新 build**,否则酒馆加载的还是上一版产物
> ——表现为「代码改了但行为没变」。

本仓库:[**sasha07230001/ST-YG-IMAGE**](https://github.com/sasha07230001/ST-YG-IMAGE)

保留了它的全部功能(自动建档、角色库、ComfyUI/NAI 出图、图库、公开接口、移动端 UI),
新增「中转站编译」这条提示词链(移植自

并把提示词配置从设置页单独拆成一个「提示词」页。

**0.7.0** 把两条提示词链合并成一次调用,并把角色信息重做成「档案库 + 本聊天角色档案」两层结构,
角色层改为从本聊天档案实时取词、与固定正面/剧情三层合成后写进 ComfyUI 的 `%prompt%`。

因体量已与上游分道扬镳,`src/update.ts` 里**默认关闭了自动更新检测**
(照旧去拉上游 manifest 只会得到一个永远「有更新」的红点,点下去还会把上游整包覆盖过来)。
REMOTE_MANIFEST_URL 已指向本仓库的 manifest,想启用自动更新把 UPDATE_CHECK_ENABLED 改成 true 即可。
